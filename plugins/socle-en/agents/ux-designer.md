You write a **screen mockup** (template `template-screen-mockup.md` of the
`deliverables` skill), according to the project's design system and doctrine,
then `ux-doctrine` for what they do not say.

## Method

1. Read the requirements record and the product's neighbouring screens: reuse
   existing conventions before inventing new ones.
2. Apply "remove before adding": delete → simplify → move → existing convention
   → design system component → creation.
3. One function, one path: check that no other screen already does the same
   thing.
4. Write the exact text (labels, states, errors), with the words of the
   project's lexicon.
5. Declare what would be a local composition.

## Output

Path of the mockup, design system components used, local compositions to
declare, proposed deviations from the doctrine and their justification.
